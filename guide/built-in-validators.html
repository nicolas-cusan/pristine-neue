Built-in validators ​

Pristine reads these attributes from your fields. The examples on this page all use new Pristine(form) with the default settings, so only their HTML is shown.

ValidatorAttributePasses when
requiredrequiredThe field isn't empty. For checkboxes and radio buttons: at least one in the group is checked.
emailtype="email"The value looks like an email address.
numbertype="number"The value is a number, such as 42, -0.5 or 1e3.
integerdata-pristine-type="integer"The value only contains digits, with no sign or decimal point.
minlengthminlength="3"The value has at least that many characters.
maxlengthmaxlength="16"The value has at most that many characters.
minmin="18"The number is at least that value. For checkboxes: at least that many in the group are checked.
maxmax="120"The number is at most that value. For checkboxes: at most that many are checked.
patternpattern="…"The value matches the regular expression.
equalsdata-pristine-equals="#id"The value is the same as that of the field with this ID.

Every attribute also works with a data-pristine- prefix, such as data-pristine-minlength="3" or data-pristine-type="email". Use the prefixed form when you don't want the browser to act on the attribute itself.

Every validator except required passes when the field is empty, so optional fields can have rules too. Add required when a value is needed.

required runs first, and when it fails it stops the other validators on that field. An empty required field only shows "This field is required".

Length ​

Try it

Submit the form to check it.

html
<form>
  <div class="field">
    <label for="length-username">Username (3 to 16 characters)</label>
    <input id="length-username" name="username" type="text" minlength="3" data-pristine-maxlength="16" />
  </div>
  <div class="field">
    <label for="length-bio">Bio (at most 40 characters)</label>
    <textarea id="length-bio" name="bio" data-pristine-maxlength="40"></textarea>
  </div>
  <button type="submit">Submit</button>
</form>

The browser's own maxlength attribute stops people from typing past the limit, so its message rarely appears. Use data-pristine-maxlength when you'd rather let people type and then show a message, as both fields here do.

Numbers ​

Try it

Submit the form to check it.

html
<form>
  <div class="field">
    <label for="number-age">Age (18 to 120)</label>
    <input id="number-age" name="age" type="number" min="18" max="120" />
  </div>
  <div class="field">
    <label for="number-seats">Seats (a whole number)</label>
    <input id="number-seats" name="seats" type="text" inputmode="numeric" data-pristine-type="integer" />
  </div>
  <button type="submit">Submit</button>
</form>

A number input (type="number") only passes on values the browser can read as a number. Anything else arrives as an empty string, which passes every validator except required. To reject input like 12abc with a message, use a text input with data-pristine-type="number" or data-pristine-type="integer", as the seats field does.

Patterns ​

Try it

Submit the form to check it.

html
<form>
  <div class="field">
    <label for="pattern-code">Product code (3 letters and 3 digits, like ABC123)</label>
    <input id="pattern-code" name="code" type="text" data-pristine-pattern="/^[a-z]{3}\d{3}$/i" data-pristine-pattern-message="Use 3 letters followed by 3 digits" />
  </div>
  <button type="submit">Submit</button>
</form>

Write the pattern as /…/flags to use flags such as i, or as a plain regular expression without slashes. It differs from the browser's own pattern check in two ways:

  • Pristine doesn't add ^ and $ for you, so a plain pattern can match anywhere in the value. Anchor it yourself.
  • In HTML, write backslashes as they are (\d). Only escape them (\\d) when the markup sits inside a JavaScript string.

Matching another field ​

Try it

Submit the form to check it.

html
<form>
  <div class="field">
    <label for="equals-password">Password</label>
    <input id="equals-password" name="password" type="password" required minlength="8" />
  </div>
  <div class="field">
    <label for="equals-confirm">Repeat the password</label>
    <input id="equals-confirm" name="confirm" type="password" required data-pristine-equals="#equals-password" />
  </div>
  <button type="submit">Submit</button>
</form>

data-pristine-equals takes an ID selector, starting with #. Pristine looks for that element in the whole document, not only in the form.

Checkbox groups ​

Try it

Pick 2 or 3 toppings

Submit the form to check it.

html
<form>
  <div class="field">
    <p class="field-label">Pick 2 or 3 toppings</p>
    <label><input type="checkbox" name="toppings[]" value="cheese" min="2" max="3" data-pristine-min-message="Pick at least ${1}" data-pristine-max-message="Pick at most ${1}" /> Cheese</label>
    <label><input type="checkbox" name="toppings[]" value="mushrooms" min="2" max="3" data-pristine-min-message="Pick at least ${1}" data-pristine-max-message="Pick at most ${1}" /> Mushrooms</label>
    <label><input type="checkbox" name="toppings[]" value="olives" min="2" max="3" data-pristine-min-message="Pick at least ${1}" data-pristine-max-message="Pick at most ${1}" /> Olives</label>
    <label><input type="checkbox" name="toppings[]" value="peppers" min="2" max="3" data-pristine-min-message="Pick at least ${1}" data-pristine-max-message="Pick at most ${1}" /> Peppers</label>
  </div>
  <button type="submit">Submit</button>
</form>

For checkboxes, required, min and max count the checked boxes that share a name (toppings and toppings[] count as the same group). Two things to keep in mind:

  • Put the attributes, and any messages, on every checkbox in the group.
  • Keep the group inside one .field wrapper, so the group shares one message.
